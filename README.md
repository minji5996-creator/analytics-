# Analytics

한국어 반응형 분석 대시보드. index.html을 열면 별도 설치 없이 실행됩니다.

- 기간별 데모 지표와 방문자 차트
- CSV 리포트 다운로드
- 모바일 반응형 화면
- 모든 수치는 데모 데이터이며 실제 분석 서비스에 연결되지 않았습니다.

배포: GitHub Pages의 main 브랜치 루트 디렉터리. main 변경 시 GitHub 기본 Pages 워크플로가 자동으로 게시합니다.

## 사용자 행동 보고서

`tracking.js`가 Google 태그를 통해 `G-7DYM9XBY66`으로 실제 사용자 행동을 전송합니다. 화면에 표시되는 데모 숫자와 별도입니다. 코드 배포 이전 행동은 복원되지 않습니다.

| 이벤트 | 측정하는 행동 |
| --- | --- |
| `click_export_report` | 리포트 내보내기 버튼 클릭 |
| `click_nav_overview` | 대시보드 메뉴 클릭 |
| `click_nav_trend` | 트래픽 분석 메뉴 클릭 |
| `click_nav_channels` | 유입 채널 메뉴 클릭 |
| `click_nav_pages` | 페이지 리포트 메뉴 클릭 |
| `click_logo` | Analytics 홈 로고 클릭 |
| `change_report_period` | 조회 기간 변경 |
| `scroll_depth_25` | 스크롤 진행률 25% 도달 |
| `scroll_depth_50` | 스크롤 진행률 50% 도달 |
| `scroll_depth_75` | 스크롤 진행률 75% 도달 |
| `scroll_depth_90` | 스크롤 진행률 90% 도달 |
| `scroll_depth_100` | 페이지 맨 아래 도달 |

스크롤 진행률은 `scrollTop / (scrollHeight - clientHeight)`입니다. 페이지 맨 위가 0%, 맨 아래가 100%입니다. 각 기준은 페이지를 새로 연 뒤 한 번만 기록하며, 위로 돌아갔다가 내려도 중복 기록하지 않습니다. 스크롤할 길이가 없는 화면은 스크롤 이벤트를 기록하지 않습니다. 메뉴를 눌러 아래 영역으로 이동하는 경우도 도달로 기록합니다. 콘텐츠를 읽었다는 의미는 아닙니다. GA4 향상된 측정의 기본 `scroll` 이벤트와 별개입니다.

### GA4 보고서 구성

- 기본 이벤트 보고서: 보고서 → 참여도 → 이벤트에서 위 이름으로 조회합니다. 이벤트 수는 클릭 횟수/각 깊이 도달 횟수이고, 총 사용자 수는 해당 행동을 한 사용자 수입니다.
- 탐색 보고서 이름: **웹사이트 버튼 클릭 및 스크롤 분석**
- 탭 1: **버튼별 클릭**. 행 = 이벤트 이름, 값 = 이벤트 수·총 사용자 수, 필터 = 이벤트 이름이 정규식 `^click_`와 일치.
- 탭 2: **스크롤 도달**. 행 = 이벤트 이름, 값 = 이벤트 수·총 사용자 수, 필터 = 이벤트 이름이 정규식 `^scroll_depth_`와 일치. 깊이 순서는 25 → 50 → 75 → 90 → 100으로 해석합니다.
- 탭 3: **기간 선택**. 필터 = 이벤트 이름이 `change_report_period`와 일치. `report_period`를 이벤트 범위 맞춤 측정기준으로 등록하면 7/30/90일 선택을 구분할 수 있습니다.
- 스크롤 도달률: 해당 깊이의 이벤트 수 ÷ 같은 기간·같은 페이지의 조회수. 사용자를 분모로 한 도달률과 다르므로 혼용하지 않습니다.

버튼 이름과 선택 기간을 별도 열로 보고 싶으면 관리 → 맞춤 정의에서 `button_name`, `report_period`를 이벤트 범위 맞춤 측정기준으로 등록합니다. 이벤트 이름만으로 구성하는 탭 1·2는 맞춤 정의 없이 구분할 수 있습니다.

새 이벤트는 실시간 보고서에서 먼저 확인하고, 일반 보고서에는 처리 이후 표시됩니다. GA4 속성에 접근/편집 권한이 있어야 탐색 보고서를 저장할 수 있습니다.
